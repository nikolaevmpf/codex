## Открыть в Obsidian

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/nikolaevmpf/obsidian.git
   ```

2. В Obsidian выберите **Открыть папку как хранилище** и укажите папку `obsidian/Obsidian` внутри клонированного репозитория.
3. Откройте заметку **Содержание**.

Дополнительные плагины для навигации не требуются. Ссылки `[[путь|название]]` открываются в Obsidian; на GitHub используйте ссылки этого README и дерево файлов.

## Структура

| Каталог | Содержание |
| --- | --- |
| `Obsidian/Linux/Arch/` | Установка, GNOME, обслуживание, виртуализация, Wi-Fi и TFTP |
| `Obsidian/Linux/Astra/` | Сеть, Ansible и активация |
| `Obsidian/Linux/NixOS/` | Установка с disko и управление конфигурацией |
| `Obsidian/Linux/Ubuntu/` | Базовая настройка, приложения, cloud-init, прокси и Zabbix |
| `Obsidian/Linux/Network/` | Сетевые менеджеры и IPv6 |
| `Obsidian/Linux/Utility/` | SSH, UFW, диски, резервное копирование и Vaultwarden |
| `Obsidian/Windows/` | LTSC, активация и локальная учётная запись |
| `Obsidian/Рецепты/` | Блюда, заготовки, выпечка и десерты |
| `Obsidian/Рецепты/Алкашка/` | Домашние напитки и записи по перегонке |
| `Obsidian/Разное/` | Размеры и личные бытовые памятки |

В корне хранилища также находятся `Задачи.md`, `Прикупить.md` и главное оглавление `Содержание.md`. Файл `Обзор.md` в каждом разделе служит его точкой входа.

## Правила ведения заметок

- Одна заметка — одна тема; первая строка — заголовок `#`.
- Для внутренних ссылок указывайте полный путь от папки `Obsidian`, без `.md`: `[[Linux/Utility/ssh|SSH]]`.
- Команды оформляйте блоками с языком (`bash`, `powershell`, `nix`), содержимое конфигураций отделяйте от команд терминала.
- Добавляйте новую заметку в `Обзор.md` соответствующего раздела, а связи с другими материалами — в блок «Связанные заметки».
- При переименовании или переносе файла обновляйте ссылки и оглавления. Автоматическое обновление ссылок можно включить в настройках Obsidian.
- Не записывайте в репозиторий пароли, приватные ключи и токены. Перед публикацией личных записей проверяйте их содержимое.

Технические заметки отражают конкретные примеры и версии из исходных записей; это не гарантия совместимости с любой системой. Неполные рецепты и личные пометки сохраняются с имеющимися уточнениями.
